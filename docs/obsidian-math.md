# Obsidian 数学公式及解释规范

## 正确格式

行内数学以单美元符号括住（例如 $x_t$），不要直接使用 LaTeX 文档里的 `\(...\)`。独立展示公式必须把开闭 `$$` 分别放在独立行：

```markdown
$$
p(\tau,\theta\mid x)=p(\theta\mid\tau,x)p(\tau\mid x).
$$

**通俗解释：** 先根据性能目标选择可能的飞机布局，再为选中的布局生成尺寸参数；两步合起来得到满足目标的飞机设计分布。
```

将论文中的 `\[...\]` 公式转成独立 `$$` 块，不要把 `$$公式$$` 挤在正文同一行。不要误改公式内部的 `\\[4pt]`：它只是换行后的间距命令。

## 解释要求

每个关键展示公式之后紧跟一段读者能读懂的说明；如果三四个展示公式属于同一组连续推导，可以在这一组之后给出明确对应的整体解释。说明应交代：

- 变量分别是什么，输入与输出是什么。
- 公式实际上在执行哪一步计算、约束或物理关系。
- 哪些结论来自原论文，哪些只是为了理解而写的简化示意。
- 不要凭空修改公式含义；若原式与实现疑似不符，保留来源并单独标注待核对。

不要改动 Markdown 代码块、YAML front matter、价格等非公式美元符号、Obsidian callout 引用结构。已有正确的 `$...$` 与 `$$` 不需重复改写。

## 格式检查

在仓库根目录运行 Python 3 命令 `python tools/check_obsidian_math.py`。脚本检查不兼容的 LaTeX 分隔符、同行展示公式、不成对的行内或展示分隔符；它不会验证数学推导正确性，也不能代替 Obsidian 阅读视图中的最终人工检查。
