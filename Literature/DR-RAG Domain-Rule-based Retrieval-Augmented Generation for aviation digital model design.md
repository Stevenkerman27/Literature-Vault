# DR-RAG: Domain-Rule-based Retrieval-Augmented Generation for aviation digital model design

> [!abstract] 摘要直译
> 在快速演进的航空制造领域，飞行器设计日益复杂，对知识整合与推理工具提出了更高要求。本文提出 DR-RAG（基于领域规则的检索增强生成），一种将领域知识图谱、基于规则的推理和数字孪生技术协同起来、用于应对设计挑战的新框架。DR-RAG 通过混合式 R2D-LLM 方法从多源数据中抽取实体，构建动态知识图谱；再借助规则融合挖掘算法创建规则库。这些规则被整合进检索增强生成流程：二分类器引导规则选择，提示模板增强大语言模型的推理。数字孪生模型可视化设计结果，并将仿真反馈写回知识图谱，形成持续改进的闭环系统。实验结果显示，在与飞行器设计相关的知识检索任务中，DR-RAG 优于其他方法，为该领域的知识处理提供了一种高效且可靠的方案。该研究既为航空制造设计提供了新的决策支持工具，也推进了大语言模型在复杂工程领域中的应用。

## 问题与动机

航空设计知识分散于设计文档、制造手册、零部件数据库、维修记录和仿真结果中。普通的大语言模型虽然能生成流畅文本，却有三个直接风险：其参数知识不能自动反映新规范和新仿真结果；其答案可能产生看似合理但不可追溯的幻觉；它对“某两个因素是否相关”与“某工序应按何种顺序执行”这两类不同推理问题没有显式区分。

标准检索增强生成（RAG）虽能给模型补充外部资料，但通常只检索文档片段，缺少可审计的关系链和过程顺序。知识图谱（KG）能保存实体与关系，却仍需要把结构化的多跳关系转化为模型可使用的上下文。论文的核心选择是：不让模型自行从长上下文中隐式归纳规则，而是先把图谱中的频繁关系和流程模式挖掘成带置信度的规则，再按问题类型检索、评分和注入提示词。

数字孪生（DT）在此不是只用于展示三维模型。作者把仿真异常、性能参数和生成的产品数据管理（PDM）报告视为可回写的新证据，使知识库、规则库和后续建议能随设计迭代更新。因此，DR-RAG 的目标是一个面向工程设计的“可追溯问答 - 结构化报告 - 仿真反馈”闭环，而非独立的聊天问答器。

### 1. 动态领域知识图谱：把异构资料变成可计算证据

知识图谱记为 $\mathcal{G}=(\mathcal{E},\mathcal{R},\mathcal{T})$：$\mathcal{E}$ 为实体集合，$\mathcal{R}$ 为关系集合，$\mathcal{T}$ 为三元组 $(e_i,r_j,e_k)$，每条三元组还带数据来源导出的置信度。其构建分两条数据通道。

- **结构化资料。** 对零部件参数库、制造工艺记录、试验数据、ERP 日志等，R2D 保留表中属性和外键语义：表行映射为节点，外键映射为边，随后按既定图谱模式装载。这避免让 LLM 从原始表格“猜测”关系，适合高精度、模式稳定的数据。
- **非结构化资料。** 对设计手册、技术报告、维修和故障记录，LLM 依据显式提示执行 NER 和 RE，产生 `(实体 1, 关系, 实体 2)` 候选三元组。提示要求实体是专有名词或技术术语，关系须语义明确，并要求给出匹配规则的置信度。
- **对齐与人工把关。** 新实体先按航空命名规则匹配旧节点；不确定时用语义相似度，阈值为 $\mathrm{Sim}(e_i,e_j)\ge0.8$，再交由领域专家审核。这一层很重要，因为后面的规则频次、置信度和检索路径都建立在实体消歧正确的前提上。

图谱更新由两类事件触发：数字孪生发现预测与实际不一致，或新技术/规范文档进入系统。新证据先被解析为候选三元组，再完成节点映射、工程原则校验和多源交叉核对；冲突属性通过多数投票解决，保留较高置信度 $c'=\max(c_{\mathrm{prev}},c_{\mathrm{new}})$。论文文字一处同时描述“新三元组替换旧值”和“多数投票”，但没有给出版本历史、来源优先级或人工审批规则，实际系统不能把这一部分视为已充分定义。

### 2. 规则挖掘：区分关联知识与过程知识

论文把图谱中的规则分成两种，原因是两类问句需要不同的证据结构。

| 规则类型 | 适用问题 | 挖掘与阈值 | 存储形式 |
| --- | --- | --- | --- |
| 关联规则 | 材料、构型、参数、性能之间“什么与什么有关” | Apriori 算法；最小支持度 0.3、最小置信度 0.6 | 一个规则头加若干关系三元组；例如高展弦比 $\rightarrow$ 减阻。 |
| 顺序规则 | 装配、测试、设计步骤“下一步是什么” | 文中描述采用 PrefixSpan 的无候选序列挖掘，但算法框标题写为 GSP；最小支持度 0.3 | 一个规则头加有序三元组链；例如部件制造 $\rightarrow$ 总装 $\rightarrow$ 系统安装测试。 |

关联规则是 $X\Rightarrow Y$，其支持度是同时包含 $X$ 和 $Y$ 的事务比例，置信度为 $\mathrm{support}(X\cup Y)/\mathrm{support}(X)$。顺序规则的置信度则是完整序列出现次数除以前缀序列出现次数。两种规则都被写成“规则头 + 三元组体”：顺序规则直接取序列首三元组构成规则头；关联规则若首尾实体有既定关系就复用该关系，否则交给 LLM 将关系抽象成通用规则头。

这种表示将规则的主题、条件和推理路径显式化，也使其能作为带元数据的图谱对象保存。图谱更新后，系统应周期性重跑规则挖掘，将新规则纳入规则库并评估旧规则是否仍适用。论文没有说明重挖掘周期、增量算法或规则漂移检测，因此“动态”更多是框架设计而非已量化验证的在线学习机制。

### 3. 规则增强检索与生成：先决定证据形态，再构造上下文

给定问题，二分类器先判定更适合关联规则还是顺序规则。特征为实体数 $E$、关系数 $R$、关键词类型向量 $K$ 和语法结构向量 $G$，即 $F=[E,R,K,G]$。文中以逻辑回归为例，将关联类记为 1、顺序类记为 0，通过最大似然和梯度下降训练，直到相邻迭代的对数似然变化小于 $10^{-6}$。这里的重要点不是逻辑回归本身，而是把“搜索哪一种图结构”变成前置的可解释决策。

分类后采取不同的遍历和评分函数：

1. **关联规则检索。** 从问题实体开始做 BFS，得到相邻或多跳候选规则。若规则含 $n$ 条三元组，分数为 $S_{\mathrm{assoc}}=\sum_{i=1}^{n}c_iw_i$；$c_i$ 是三元组置信度，$w_i$ 是该三元组与答案相关性的权重。
2. **顺序规则检索。** 采用 DFS 沿过程链深入，只保留顺序匹配的候选。分数为 $S_{\mathrm{seq}}=\prod_{i=1}^{n}c_iw_i$。乘积会强烈惩罚任一低可信步骤，符合“一个工序链条失效则整链可靠性下降”的语义，但也会偏向短序列。
3. **权重估计与排序。** 权重用三元组 $T$ 与答案 $A$ 的互信息 $I(T;A)$ 表示：越常与正确答案共同出现、越有区分性的三元组权重越高。候选按分数排序，将高置信规则连同检索文档传给生成器。
4. **提示构造。** 提示固定包括背景、规则和原问题。关联问题中列出带分数的无序关系，顺序问题中按原顺序列出三元组，并要求 LLM 按规则说明或生成方案。这样，模型生成的可追溯依据来自显式规则，而不只是向量相似检索到的段落。

### 4. 数字孪生与结构化报告：把建议接入设计环境

LLM 的输出不是直接作为自然语言建议结束。作者设计 XML 提示模板，把机型、设计阶段、部件、几何形状、材料、展弦比、升力系数等字段写成报告。该 XML 由 Dassault Systemes 的 3DEXPERIENCE 平台读取：标签映射到三维模型属性，新部件可被加入模型，参数随后影响气动计算与可视化。平台侧还应执行模式校验；缺字段、格式不符或类型不匹配时按预定义规则修正或转人工复核，并把错误案例用于后续微调。

反馈回路的输入是数字孪生检测到的故障实体及 XML 属性值。系统先标记 KG 中不存在的参数，再把它们和故障关联成局部子图；子图经过语义对齐写回 KG，并转为高置信生产规则。需要注意，论文将“更新后的图谱用于细化 LLM 训练”作为工作流的一部分，但未报告实际微调数据、训练策略或对比实验；在工程实施中，更稳妥的做法应是先将更新仅用于检索上下文，再为微调设置版本、离线评测和安全审核。

## 实验设置与结果

### 数据、任务与对照

- **运行环境。** Ubuntu 20.04 Long-Term Support（长期支持版）系统与 NVIDIA A100 40 GB GPU。
- **知识来源。** 一家航空制造企业的 200 余条维修日志，记录故障代码、修复过程与部件寿命；Airbus A320 和 Boeing 787 的维护手册；以及互联网航空制造文章。尽管论文称数据为多模态，实验描述的可复现实质资料主要是表格/日志和文本手册，未给出图像、音频或视频的处理与评测细节。
- **评测集。** 关联问答集含 138 个航空设计 QA，考察部件、系统和设计原则关系；顺序问答集含 47 个制造手册流程，考察工序知识。规模较小且由作者自行构建，论文没有给出训练/验证/测试拆分、标注协议、问题示例分布或公开获取方式。
- **模型与对照。** 在 Llama-3-8B-Instruct、GPT-4o-mini、Qwen-7B 和 DeepSeek-R1 四种基础 LLM 上，比较纯提示、标准 RAG、GNN-RAG、RuleRAG 和 DR-RAG。核心指标是 Recall@10 与 Hits@1，前者看候选集中是否覆盖正确知识，后者看正确答案是否排在首位。

### 关联问答：规则引导提升检索覆盖与首位命中

DR-RAG 在四种基础模型上均取得最高或接近最高的 Recall@10，并显著优于纯提示和标准 RAG：Llama-3 为 75.43% / 55.67%，GPT-4o-mini 为 76.17% / 55.84%，Qwen-7B 为 75.04% / 57.41%，DeepSeek-R1 为 77.42% / 51.40%（依次为 Recall@10 / Hits@1）。

以同一基础模型的最佳常规规则对照 RuleRAG 比较，Recall@10 的绝对提升约为 2.2 至 3.0 个百分点；Hits@1 的表现不完全一致，例如 Qwen-7B 从 53.78% 升至 57.41%，GPT-4o-mini 从 47.45% 升至 55.84%，但 DeepSeek-R1 的 Hits@1 从 RuleRAG 的 45.53% 升至 51.40%。这支持“显式关联规则的图遍历、评分与提示注入”确实比只有检索文档更适合关系型航空知识，但没有消融实验来区分收益究竟来自分类器、BFS、互信息权重还是提示格式。

### 顺序问答：对过程链有更强的召回，但首位指标存在异常

DR-RAG 在顺序问答的 Recall@10 同样最高：Llama-3 为 65.63%，GPT-4o-mini 为 63.85%，Qwen-7B 为 62.51%，DeepSeek-R1 为 64.16%。相对 RuleRAG 的提升约为 1.6 至 12.8 个百分点，其中 GPT-4o-mini 的提升最大（51.01% 到 63.85%），说明 DFS 与顺序规则对程序性知识具有实际价值。

不过表中 GPT-4o-mini 的 GNN-RAG Hits@1 为 57.22%、RuleRAG 为 59.56%，均高于 DR-RAG 的 47.34%，这与“DR-RAG 在两个指标都最佳”的正文结论不一致。笔记应将此看作论文报告的内部矛盾，而不是忽略它。除此之外，DR-RAG 在 Llama-3、Qwen-7B、DeepSeek-R1 的 Hits@1 分别为 42.14%、46.10%、48.67%，均高于同表中的标准 RAG 和 GNN-RAG。

### XML 报告与设计案例

在 XML 生成评测中，DR-RAG 的属性召回率为 66%、精确率为 68%，高于 RuleRAG 的 62% / 64% 和 GNN-RAG 的 60% / 未在正文中列出的精确数值。精确率定义为 $1-\frac{\text{幻觉属性数}}{\text{生成属性总数}}$，因而它直接度量结构化报告中不存在于证据或规范中的字段比例。

案例以宽体远程飞机机翼优化为例。系统检索“主动流动控制装置与升阻比改善相关”的关联规则（置信度 0.85），生成建议后让数字孪生在不同飞行工况下模拟燃油效率和结构完整性，再将性能结果回写图谱。该案例表明了闭环如何工作，但论文没有给出迭代次数、基线设计的数值性能、仿真模型或统计显著性；作者也明确承认尚不能用大量定量实验系统证明数字孪生对设计精度或开发周期的提升。因此，实验直接证明的是知识检索效果和 XML 属性质量，而不是实际飞行器优化收益。

## 关键贡献

1. 将结构化关系数据转换、LLM 文本抽取、实体对齐和专家审核组合为可更新的航空领域 KG，而不是只构建一次静态文档库。
2. 将频繁知识显式区分为关联规则与顺序规则，配套问题二分类、BFS/DFS 检索、不同评分函数和规则化提示，使推理路径可以被展示、审查和排序。
3. 用 XML 报告连接 LLM 与 3DEXPERIENCE 数字孪生平台，并设计从异常和仿真结果回写图谱、再更新规则的概念闭环。
4. 在四种 LLM、两个航空问答集上显示规则增强检索相对标准 RAG、GNN-RAG 和 RuleRAG 的总体优势，尤其提高了顺序流程问题的 Recall@10。

## 局限与启发

- **规则质量上限受数据和实体对齐约束。** 支持度、置信度和互信息都从已有记录估计；稀有但安全关键的故障、从未发生过的新构型，可能在频繁模式挖掘中被过滤。0.3 支持度和 0.6 置信度没有灵敏度分析。
- **问题分类是单标签假设。** 真实设计问题通常同时包含关系与流程，例如“选定材料后按何步骤验证并满足何性能”。二分类器强制选关联或顺序之一，缺少混合检索、置信度回退和人工接管机制。
- **数字孪生闭环尚未被充分实证。** 论文展示了接口、XML 校验和回写流程，但没有说明与仿真器的实际耦合频率、物理保真度、版本追踪或更新延迟，也未以对照实验证明闭环减少了设计时间。
- **实验可复现性有限。** 私有日志、作者自建小规模题集和未公开的数据划分限制结论外推；还缺少多次随机运行、显著性检验、成本/延迟及错误案例评估。
- **结构化输出仍不足以直接放行。** 68% 的 XML 精确率意味着约三分之一生成属性仍可能不可靠。对安全关键航空设计，应让规则、检索证据、模式校验和人工审批共同构成发布门，而不能把 LLM 输出视为经验证的设计变更。
- **可复用设计原则。** 将图谱边、规则评分与生成提示之间保留可追溯映射；对静态标准、实时仿真和人工修订实施来源与版本管理；将“回答正确”与“工程建议经仿真验证”分成不同的评测层。
