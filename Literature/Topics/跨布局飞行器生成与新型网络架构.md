# 跨布局飞行器生成与新型网络架构

> [!abstract] 研究主问题
> **究竟什么被生成：** 固定布局的连续几何变量？任意外形点云？显式组件拓扑树？已预训练的子系统之间的装配关系？还是只有气动场代理？本专题将这五件事分开，再梳理 GAN → Diffusion/DiT → Neural Operator/Physics Attention → 模块化生成系统的可验证研究脉络。

> [!important] 使用网络名字识别方法的常见误区
> **“使用了 Transolver”并不等于“以 Transolver 生成飞机”**。论文可能使用神经算子作为 flow-field surrogate，生成器仍然是 DDPM、DiT、GAN 或拓扑概率模型。上述表格把生成器、评价器和物理验证分别列出，以避免误导性的模型标签。

## 2. 代表性研究脉络

~~~mermaid
flowchart TB
  R[需求/性能/工况] --> C[连续条件表达]
  R --> T[离散拓扑后验]
  GAN[PaDGAN / PcDGAN / Range-GAN] -. range / diversity concepts .-> C
  C --> D[条件 Diffusion 或 DiT]
  T --> MIX[MixeDiT 采样拓扑]
  MIX --> MASK[MaskeDiT 按拓扑生成连续参数]
  C --> POINT[多形状族点云 AE + latent diffusion]
  D --> BWB[BlendedNet++ BWB 九维扩散]
  BWB --> OPT[梯度优化精修]
  OPT --> CFD[FUN3D / CFD 复核]
  TRANS[Transolver/FiLMNet 物理场代理] --> OPT
  MASK --> ASSEMBLE[部件系统协调]
  POINT -. 需要CAD/接口验证 .-> ASSEMBLE
  ASSEMBLE --> GLUE[GLUE 生成器协调 + 约束]
  GLUE --> VERIFY[几何与物理真实性检查]
~~~

**关系等级说明：**
- “Range-GAN → 条件扩散”的连接是**研究问题的延续和条件损失类比**，不是后作逐项直接继承 GAN 代码。
- “MixeDiT → MaskeDiT”是**同一论文真实两阶段生成**。
- “BlendedNet++ 的 CDM → 优化 → FUN3D”是**同一论文真实实验链路**。
- “MixeDiT 与 GLUE”或“共享点云 latent 与 GLUE”的虚线是**建议研究组合**，没有跨论文联合复现证据。

## 3. 五种关键技术突破不能混为一谈

### 3.1 从“固定维参数”到“离散拓扑 + 变长参数”

**难点**：如果某个飞机只有一片翼、另一个有两片翼，所需连续参数个数不同；不能把不存在的组件当作真实几何参数。[[Literature/transformer/Do Diffusion Models Dream of Electric Planes Discrete and Continuous Simulation-Based Inference for Aircraft Design|MixeDiT–MaskeDiT]] 明确分解 \(p(\tau,\theta\mid x)\)，并对不存在组件使用 attention/loss 掩码。这是与固定九维 BWB 参数扩散最本质的区别。

### 3.2 从“固定拓扑 CAD”到“共享点云潜空间”

[[Literature/基于生成式模型的三维气动外形设计框架|三维气动形状基础模型]] 在统一的点云表示下学习几何，并可重建轴对称与翼身融合体两类外形。**优点**是可以跨部分先验参数化限制；**代价**是点云本身缺少装配拓扑、曲面/体积分界、内部容积和可微工程约束接口。所谓“跨布局”主要是跨**外形类别**，不是无限制新拓扑组合。

### 3.3 从“条件固定齐全”到“条件集合稀疏”

[[Literature/基于扩散Transformer的多约束气动外形生成式设计|多约束 DiT]] 通过 Fourier 条件 token + 全局/逐项 dropout 处理不完整输入。它与拓扑掩码**不同**：条件 dropout 控制“哪些需求已知”，拓扑 mask 控制“哪些几何变量物理存在”。

### 3.4 从“生成器输出即可使用”到“代理 + 高保真闭环”

[[Literature/BlendedNet++ A Dataset and Benchmark for Field-Resolved Aerodynamics and Inverse Design of Blended Wing Body Aircraft|BlendedNet++]] 使用 Transolver 等预测压力/摩擦场，扩散生成 BWB 九维参数，再使用代理梯度做几何 refinement，最后选 2,500 组做 FUN3D CFD 重算。应与仅靠代理满足率的 GAN 论文区分，尤其注意其单几何单工况及 \(M<0.5\) 的数据域限制。

### 3.5 从“端到端单模型”到“冻结子系统协调”

[[Literature/GLUE Coordinating Pre-Trained Generative Models for System-Level Design|GLUE]] 不要求所有组件使用相同生成架构或共享训练集，而是用共享系统级 latent 配合可微几何约束协调冻结的 wing、fuselage、internals 模型。它强调**跨模块界面可行性**，却还没有完成变长组件拓扑、大规模可微 RANS 和高保真结构统一评估。

## 4. 对跨布局飞行器生成器的可检验架构建议（非论文结论）

候选的系统分层：

1. **拓扑层** \(p(\tau\mid c)\)：定义可选翼面、机身、推进系统与它们的离散连接。
2. **参数层** \(p(\theta_\tau\mid\tau,c,z)\)：变长部件参数、尺寸和站位；条件输入允许部分缺失。
3. **几何层**：把模块 latent/参数解码成可微几何，显式检测交叠、翼根连接、内部容积和厚度。
4. **场评价层**：使用 Transolver / LinearNO / 其他神经算子预测局部压力、剪切；同时积分到全局气动力矩。
5. **物理校验层**：多工况、CFD 真值、结构、几何梯度与布局 OOD，避免优化利用代理误差。
6. **可选协调器**：类似 GLUE 的共享系统 latent；如果拓扑可变，则协调器应支持组件集合/图，而非固定 22 维和固定部件模板。

### 先做什么消融？

| 研究假设 | 必须比较的基线 | 核心验收 |
|---|---|---|
| 拓扑分层是否必要 | 单一固定模板扩散 vs 两阶段拓扑扩散 | 已见/未见组合的可行率、真实几何合法性 |
| 统一 latent 是否泛化跨形状族 | 分别训练轴对称/BWB vs 共享编码器 | 跨类别重建、Chamfer、CAD 水密/接口检查 |
| 条件 token 是否比简单拼接更好 | 条件向量 concat / adaLN / 条件 token | 缺失条件组合的误差与联合满足率 |
| 场代理是否真正指导优化 | FiLM/Transolver/LinearNO 对照；固定 CFD 数据 | \(C_p,C_f,C_L,C_D,C_M\)、梯度、推理成本 |
| 多组件协调是否避免虚假可行 | 逐组件独立采样 vs GLUE 类约束协调 | 连接、装载、升力、质量、多样性 |

## 6. 优先阅读次序

1. [[Literature/transformer/Do Diffusion Models Dream of Electric Planes Discrete and Continuous Simulation-Based Inference for Aircraft Design|MixeDiT–MaskeDiT]]：先真正理解跨拓扑与变长表示。
2. [[Literature/GLUE Coordinating Pre-Trained Generative Models for System-Level Design|GLUE]]：理解复杂系统中已训练组件的约束协同。
3. [[Literature/BlendedNet++ A Dataset and Benchmark for Field-Resolved Aerodynamics and Inverse Design of Blended Wing Body Aircraft|BlendedNet++]]：理解真实 CFD 数据和代理→生成→精修→重算。
4. [[Literature/基于生成式模型的三维气动外形设计框架|点云几何基础模型]]：理解跨外形类别的几何潜空间，同时警惕 CAD 接口问题。
5. [[Literature/基于扩散Transformer的多约束气动外形生成式设计|多约束 DiT]]：理解不完整任务条件的编码/训练。
6. 之后根据项目瓶颈，从 [[Literature/待读论文清单|待读清单]] 选择动态条件引导、精确约束投影、神经算子或 DDIM 加速进行精读。
